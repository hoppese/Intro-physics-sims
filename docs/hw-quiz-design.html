Intro Physics Sims — design note

Sim-Embedded Homework Quizzes

A design for turning the sims into graded practice surfaces: a question posed against the live sim, a checked answer, a recorded score. Scoping document — no code written yet beyond what already ships.

01

Goal

Online homework that runs on our own stack — the sims plus a lightweight question layer — with scores that land in Moodle. Target framing from the roadmap: this is the path off Mastering Physics for next spring. The near-term win is smaller: give students a way to practice against a sim and know whether they got it right, which nothing currently does.

Related notes: the roadmap's "Native Moodle vs. external + LTI" question (this doc takes a position on it in §07), and the parked idea to "generalise Random problem into a real question engine" — that idea is this feature.

02

What already ships

More of the machinery exists than you might expect:

  • Random-problem generators — 40 of 43 sims. Each doRandom() / randomSetup() / __menuRandom() picks fresh slider values and sets hide:true. The three without: circuit-lab (Beta), radiation-wiggling-charge, e-fields-conductors-and-insulators.
  • The Random problem → Show solution loop. The header button already runs a three-click cycle: randomize + hide answers → reveal → new problem. This is the quiz loop, minus the question text and the answer box.
  • The sim is its own answer key. Generators only randomize inputs; the sim's physics engine then computes every derived quantity and simply masks it while hide is true. There is a correct number for every readout at every moment — it just isn't checked against anything.
  • Predict-then-reveal worked examples. oscillation-explorer already asks the student to read A, T, φ₀ off a random curve before revealing. The interaction pattern for "answer, then check" is proven in-codebase.
  • A POST-to-Worker pattern. The "Submit bug" feature POSTs from every sim to a Cloudflare Worker (sims-api.sethhopper.com) that writes to the repo. A quiz-results endpoint is the same shape.
  • Sims already embed in Moodle. Class-prep questions run the sims full-size in an iframe. Whatever the quiz layer does, it has to work inside that iframe too.
03

The gap

Between "randomize and hide" and "graded quiz question" there are five missing pieces:

PieceStatus
A promptMissing. The sim hides numbers but never says "find the impact speed."
An answer inputMissing. No field to type a value or pick a choice.
A checkMissing, but trivial — compare the typed value to the sim's own computed value with a tolerance.
A score + attempt recordMissing. No notion of correct/incorrect, attempts used, or time.
A path to the gradebookMissing. This is the real work — see §07.
04

The Quiz overlay

A fourth overlay type alongside Info / Worked example / Random problem, opened from the ☰ menu and (in quiz mode) from a header button. It does not replace the free-play sim — it wraps it.

Layout, top to bottom:

  1. Prompt. One question, tied to the current randomized scenario. "The ball is tossed from a 15 m ledge at 8 m/s. How fast is it moving when it lands?"
  2. The live sim. Still fully interactive — the student can drag, play the animation, read the input sliders. Only the quantity being asked about (and anything that would give it away) stays hidden.
  3. Answer row. A numeric field with a unit label, or a set of multiple-choice buttons, or an angle/vector entry (§06).
  4. Check. Compares to the sim's computed value within tolerance. Shows correct / close / not-yet, and on the final attempt reveals the worked steps (reuse the existing Worked-example content).
  5. Next. New random scenario, same question template.
Why wrap the sim rather than build separate questions: the sim already renders the scenario, computes the answer, and randomizes cleanly. A standalone question bank would duplicate all three and drift out of sync. The sim stays the single source of truth; the quiz layer is thin.
05

Per-sim question spec

Each sim gains one small method describing what it can ask. Everything else (rendering, physics, randomizing) is already there.

quiz() {
  return {
    // reuse the existing generator for the scenario
    randomize: () => this.doRandom(),
    questions: [
      {
        id: 'impact-v',
        prompt: 'How fast is the ball moving when it lands?',
        answer: () => this.impactV(),      // the sim's own computed value
        unit: 'm/s',
        tol:  { type: 'percent', value: 3 },
        hideWhileAsked: ['v', 'vGraph'],   // readouts to mask
      },
      {
        id: 'apex',
        prompt: 'What is the peak height above the ground?',
        answer: () => this.maxH(),
        unit: 'm', tol: { type: 'percent', value: 3 },
        hideWhileAsked: ['apex'],
      },
    ],
  };
}

Authoring one of these is ~15 minutes per sim once the overlay exists. Start with the sims that have a single clean numeric answer: drop-and-toss, center-of-mass, universal-gravitation, kinetic-theory-speeds, rc-charging, lens-/mirror-ray-tracer, ray-optics, ampere-loop, lorentz-force, faraday-induction, rail-flux-bar, polarization-malus, kepler's-laws. That is ~15 sims — a full problem set — without touching the harder field-map sims.

07

Getting grades to Moodle

Three options, cheapest to most robust:

C · Results Worker + CSV import (recommended to start)

The sim POSTs each finished attempt { student, sim, questionId, seed, correct, attempts, score, ts } to a Cloudflare Worker — the same pattern as the bug reporter. The Worker appends to storage (KV, D1, or a Google Sheet). You download a CSV and import into the Moodle gradebook, or read the sheet directly. Identity comes from a token in the iframe URL that the Moodle question template fills in with the student's ID. No real-time gradebook, but it unblocks a graded pilot this term with a few days of work.

B · LTI 1.3 tool (the real target)

Wrap the quiz in an LTI 1.3 launch. Moodle launches the sim as an external tool; the tool pushes the score back through Assignment & Grade Services and it lands in the gradebook automatically, hidden until the due date. This is what actually replaces Mastering Physics. Needs an LTI service (a small always-on app or a Worker with the LTI libraries) and per-course tool registration. Weeks, not days — but it is the spring-term goal.

A · Native Moodle embedded question

Make the quiz a Moodle question type (or a STACK / custom JS question) that reads the sim's score out of the iframe via postMessage. Grading is then fully built in. The catch: bridging an arbitrary iframe's internal state into a Moodle question's grade is fiddly and version-fragile. Not recommended as the primary path, though the postMessage hook is worth building anyway — option A and option C can share it.

Recommendation: build the Quiz overlay + a postMessage "attempt finished" event + option C now, for a graded pilot this term. Design the overlay's score-reporting so that swapping option C's Worker POST for option B's LTI grade push is a one-function change. Do the LTI work over winter break, aimed at spring.
08

Rollout

Phase 0

Prototype on one sim

Quiz overlay on drop-and-toss. Numeric answer, tolerance check, self-check only — no recording. Proves the interaction and the "sim is the answer key" approach. ~2 days.

Phase 1

A problem set + recording

quiz() specs for the ~15 clean-numeric sims. postMessage attempt event. Results Worker + CSV. Run one graded assignment. ~1–2 weeks.

Phase 2

Concept questions + graph clicks

Multiple-choice checkpoints tied to Info panels; read-the-graph on the wave sims. Widen coverage toward all 40 randomizable sims.

Phase 3

LTI 1.3

Grades auto-land in the Moodle gradebook. Retire Mastering Physics. Winter build, spring launch.

09

Decisions needed

  1. Graded for credit, or practice-only to start? Class preps are currently completion-based. Is the quiz a new graded assignment, or a self-check bolted onto the existing preps?
  2. Attempts and penalties. One shot, or unlimited with decreasing credit? Does opening "Show solution" forfeit the question?
  3. Tolerance policy. Flat percent (3%? 5%?), significant figures, or per-question in the spec? Students will ask.
  4. Unit of assignment. One sim = one question, or an assignment that chains several sims' questions into a set?
  5. Question mix for v1. Numeric only, or numeric + a concept MC per sim from the start?
  6. Pilot grade path. Is a CSV / Google Sheet acceptable for a first graded run, or does it need to hit the Moodle gradebook directly (which means starting on LTI)?
  7. Identity. Confirm the Moodle question template can inject the student's ID into the iframe URL — the whole recording story depends on it.
